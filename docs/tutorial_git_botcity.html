01GitFlow corporativo

Estrutura de branches para automações industriais

No projeto da LG Electronics, o código produzido é propriedade intelectual da empresa. Repositórios são privados e cada mudança precisa de rastreabilidade. O GitFlow define quem pode alterar o quê e quando.

📌 Contexto do projeto
Processo: Conferência diária de lotes de inspeção — Área de Qualidade · LG/PIM.
Repositório: conferencia-lotes-qualidade (privado, sua conta + instrutor como colaborador).
01
Criar a estrutura de branches do projeto
Aula 6 · ~20 min
▶

O GitFlow para projetos de automação corporativa usa exatamente estas branches — não mais, não menos no início:

terminal — criar estrutura inicial
bash 
# 1. Clonar o repositório (já criado no GitHub como privado)
git clone git@github.com:SEU_USUARIO/conferencia-lotes-qualidade.git
cd conferencia-lotes-qualidade

# 2. Criar branch develop a partir de main
git checkout -b develop
git push -u origin develop

# 3. Criar a primeira feature branch (PDD já feito, agora é código)
git checkout develop
git checkout -b feature/S2-estrutura-projeto

# 4. Verificar situação
git branch -a
# * feature/S2-estrutura-projeto
#   develop
#   main
#   remotes/origin/develop
#   remotes/origin/main
BranchQuem usaRegraProtegida?
mainNinguém diretamenteSó recebe via PR de release/* ou hotfix/*✅ Sim
developToda a equipeRecebe merges de feature/* via PR✅ Sim
feature/S2-*Desenvolvedor da featureCriada a partir de develop, volta via PR❌ Não
release/v0.x.0Responsável técnicoCriada de develop, merge em main + develop❌ Não
hotfix/descricaoResponsável técnicoCriada de main, merge em main + develop❌ Não
⚠️ Proteger branches no GitHub
Em Settings → Branches → Branch protection rules, proteja main e develop:
  • Require a pull request before merging (1 reviewer mínimo)
  • Require status checks to pass (CI deve estar verde)
  • Do not allow bypassing the above settings
Sem isso, qualquer membro do time pode fazer push direto em main — invalidando toda a rastreabilidade.
02Commits semânticos

Histórico como documentação técnica auditável

Em ambiente industrial, o histórico do Git é evidência. Um commit chamado "atualização" não informa nada a um auditor. Conventional Commits resolvem isso com estrutura rastreável automática.

02
Padrão Conventional Commits para automações
Aula 7 · referência permanente
▶
formato do commit texto 
tipo(escopo): descrição curta no imperativo

[corpo opcional — explica o POR QUÊ, não o O QUÊ]

[rodapé — refs de issues, breaking changes]
TipoQuando usarExemplo do projeto
featNova funcionalidadefeat(validacao): adicionar RN07 — obs. obrigatória em reprovado
fixCorrigir bugfix(status): normalizar NOK→REPROVADO antes de validar
docsDocumentaçãodocs(pdd): atualizar seção 12 com exceção EX03
testTestestest(base_referencia): adicionar caso lote inexistente
refactorSem bug, sem featurerefactor(main): extrair validação para src/validacao.py
choreInfraestrutura, depschore(deps): atualizar botcity-maestro-sdk para 2.0.0
perfPerformanceperf(base): usar frozenset para lookup O(1) na base de referência
exemplos reais do projeto de lotes 
# ✅ Commit correto — rastreável ao PDD
git commit -m "feat(validacao): implementar RN03 — verificar lote na base de referência

Adiciona consulta à base_referencia_lotes.csv usando frozenset para
performance O(1). Lotes inexistentes geram divergência com código
EX02 conforme PDD seção 13.

Ref: PDD v0.2 seção 12, regra RN03"

# ✅ Commit de correção com referência ao incidente
git commit -m "fix(status): aceitar 'OK' como sinônimo de APROVADO (RN05)

Rafael (operador) confirmou que o sistema legado às vezes exporta
'OK' em vez de 'APROVADO'. A regra informal foi documentada no PDD
como RN05 e agora está implementada.

Closes #3"

# ❌ Commit ruim — não use assim
git commit -m "atualização"
git commit -m "ajustes finais"
git commit -m "correção de bug"
✅ Gabarito de commit semântico
Um commit bem feito responde O QUÊ mudou (tipo + escopo) e POR QUÊ (corpo). O como está no diff — não precisa no commit. Se o corpo menciona uma regra do PDD (RN03, EX02) ou fecha uma issue (#3), o histórico do Git vira documentação técnica auditável.

04B
Cenário B — Hotfix urgente em produção
Aula 9 · bug descoberto às 8h05
▶

O bot foi para produção ontem (v0.1.0). Hoje de manhã, o supervisor reportou que lotes com status NOK estão sendo classificados como ambíguos em vez de REPROVADO. O Convenio exige correção rastreável.

fluxo de hotfix completo 
# 1. Criar hotfix a partir de main (não de develop!)
git checkout main
git checkout -b hotfix/fix-nok-normalizacao

# 2. Corrigir o bug
# Antes: STATUS_MAP sem NOK
# Depois:
STATUS_MAP = {
    'OK': 'APROVADO',
    'NOK': 'REPROVADO',    # ← CORREÇÃO
    'REPROV.': 'REPROVADO',
}

# 3. Commit com referência ao incidente
git add src/validacao.py
git commit -m "fix(status): adicionar NOK→REPROVADO na normalização (RN05)

Bug: status NOK estava sendo classificado como ambíguo em vez de
REPROVADO. Causa: STATUS_MAP incompleto — RN05 do PDD não foi
totalmente implementado.

Impacto: lotes NOK do turno A de hoje precisam ser reprocessados
manualmente (confirmar com Rafael).

Fixes #8"

# 4. Merge em main COM TAG IMEDIATA
git checkout main
git merge hotfix/fix-nok-normalizacao --no-ff
git tag -a v0.1.1 -m "hotfix: normalização NOK→REPROVADO (RN05)"
git push origin main --tags

# 5. OBRIGATÓRIO: merge também em develop
git checkout develop
git merge hotfix/fix-nok-normalizacao --no-ff
git push origin develop

# 6. Deletar a branch de hotfix
git branch -d hotfix/fix-nok-normalizacao
git push origin --delete hotfix/fix-nok-normalizacao
⚠️ Erro crítico — esquecer de mergear hotfix em develop
Se o hotfix vai apenas para main e não para develop, na próxima release o bug vai reaparecer — porque develop ainda tem o código antigo. Isso é o erro mais comum com GitFlow. Sempre: main + develop, nessa ordem.

Cenário C — Stash e bisect para diagnóstico
Comandos de emergência
▶
stash + bisect
# git stash — guardar trabalho em andamento sem commitar
# Situação: você está editando validacao.py, precisa trocar de branch urgente
git stash push -m "wip: implementando RN06 — status ambíguo"
git checkout main  # agora pode trocar sem perder o trabalho
# ... faz o que precisava ...
git checkout feature/S2-validacao
git stash pop      # restaura o trabalho
git stash list     # ver todos os stashes

# git bisect — encontrar qual commit introduziu um bug
# Situação: o bot funcionava ontem, hoje falha. Qual commit causou?
git bisect start
git bisect bad HEAD           # commit atual tem o bug
git bisect good v0.1.0        # esta tag estava boa
# Git vai checkout em commits intermediários automaticamente
# Para cada um, você testa e informa:
git bisect good    # se este commit NÃO tem o bug
git bisect bad     # se este commit TEM o bug
# Ao final: "abc1234 is the first bad commit"
git bisect reset   # volta ao HEAD após identificar o culpado

# git revert — desfazer commit sem reescrever histórico
# USE SEMPRE REVERT, nunca reset --hard em branches compartilhadas
git revert abc1234 --no-edit
# Cria um novo commit que desfaz o abc1234, histórico intacto

bot.py — entry point obrigatório 
#!/usr/bin/env python3
"""
Bot de Conferência de Lotes de Inspeção — LG Electronics · Qualidade
Convênio N.º 005/2025 — INOVA / IFAM / LG Electronics do Brasil Ltda.

Entry point para execução local e via BotCity Maestro.
"""
import sys, time, logging
from src.config    import carregar_configuracao
from src.main      import executar_pipeline
from src.logger    import configurar_logging

logging.basicConfig(level=logging.INFO,
    format='[%(asctime)s] %(levelname)-8s %(name)s: %(message)s')
logger = logging.getLogger('bot-conferencia-lotes')


def main() -> int:
    """Ponto de entrada do bot. Retorna 0 (sucesso) ou 1 (falha)."""
    t0 = time.time()
    logger.info('Bot iniciado — Conferência de Lotes de Inspeção')

    try:
        config = carregar_configuracao()

        # Verificar pré-condições antes de processar
        import os
        if not os.path.exists(config.planilha_path):
            logger.critical(f'Planilha não encontrada: {config.planilha_path}')
            return 1

        if not os.path.exists(config.base_referencia_path):
            logger.critical(f'Base de referência não encontrada: {config.base_referencia_path}')
            return 1

        # Executar o pipeline de validação
        resultado = executar_pipeline(config)
        duracao   = round(time.time() - t0, 2)

        logger.info(
            f'Concluído em {duracao}s — '
            f'Total: {resultado.total} | '
            f'Válidos: {resultado.validos} | '
            f'Divergências: {resultado.divergencias} | '
            f'Ambíguos: {resultado.ambiguos}'
        )
        return 0

    except except Exception as e:
        logger.critical(f'Falha crítica: {e}', exc_info=True)
        return 1


if __name__ == '__main__':
    sys.exit(main())

bot.py — versão com integração Maestro 
from botcity.maestro import BotMaestroSDK, AutomationTaskFinishStatus
import sys, time, logging, os
from src.config  import carregar_configuracao
from src.main    import executar_pipeline

logger = logging.getLogger('bot-conferencia-lotes')


def main():
    config = carregar_configuracao()
    t0 = time.time()

    # Modo Maestro ou local, conforme MAESTRO_ENABLED
    maestro = None
    task    = None

    if config.maestro_enabled:
        # from_sys_args() lê --server e --token injetados pelo runner
        maestro = BotMaestroSDK.from_sys_args()
        task    = maestro.get_task()
        logger.info(f'Executando via Maestro | task_id={task.id}')
    else:
        logger.info('Executando localmente (MAESTRO_ENABLED=false)')

    try:
        resultado = executar_pipeline(config)
        duracao   = round(time.time() - t0, 2)

        if task:
            task.finish(
                status=AutomationTaskFinishStatus.SUCCESS,
                message=(
                    f'Total: {resultado.total} | '
                    f'Válidos: {resultado.validos} | '
                    f'Divergências: {resultado.divergencias} | '
                    f'Ambíguos: {resultado.ambiguos} | '
                    f'Duração: {duracao}s'
                )
            )
            # Enviar relatório como artefato para o painel do Maestro
            import glob
            for report in glob.glob(f'{config.output_dir}/*.xlsx'):
                maestro.post_artifact(
                    task_id=task.id,
                    artifact_name=os.path.basename(report),
                    filepath=report
                )
        sys.exit(0)

    except except Exception as e:
        logger.critical(f'Falha crítica: {e}', exc_info=True)
        if task:
            task.finish(
                status=AutomationTaskFinishStatus.FAILED,
                message=str(e)
            )
        sys.exit(1)


if __name__ == '__main__':
    main()

10DataPool

A fila que garante que nenhum registro é perdido

Sem DataPool: se o bot falhar na linha 187 de 300, os outros 113 são perdidos. Com DataPool: cada item tem status próprio. Falhas em itens isolados não param o processamento dos demais.

Popular e consumir o DataPool com tratamento de erros
Aula 12 · arquitetura de robustez
▶
📐 Regra arquitetural — quem popula não processa
O DataPool deve ser populado por um processo separado do bot que consome. Se o mesmo bot popula e consome, você perde a capacidade de reprocessar apenas os erros sem recarregar todos os dados. No projeto: scripts/populate_datapool.py popula · bot.py consome.
scripts/populate_datapool.py 
from botcity.maestro import BotMaestroSDK
from botcity.maestro.model import DataPoolEntry
import pandas as pd, os


def popular_datapool(maestro, datapool_label, caminho_planilha):
    df = pd.read_excel(caminho_planilha, dtype=str).fillna('')

    # Validação mínima antes de popular
    obrigatorias = {'lote_id', 'produto', 'linha', 'turno',
                    'status', 'responsavel', 'data'}
    presentes = set(df.columns.str.lower())
    if not obrigatorias.issubset(presentes):
        faltando = obrigatorias - presentes
        raise ValueError(f'Colunas obrigatórias ausentes: {faltando}')

    df.columns = df.columns.str.lower()
    dp = maestro.datapool(datapool_label)
    total = 0

    for idx, row in df.iterrows():
        entry = DataPoolEntry(values={
            'lote_id':     row['lote_id'],
            'produto':     row['produto'],
            'linha':       row['linha'],
            'turno':       row['turno'],
            'status':      row['status'],
            'responsavel': row['responsavel'],
            'data':        row['data'],
            'observacao':  row.get('observacao', ''),
            'linha_idx':   str(idx + 2),
        })
        dp.create_entry(entry)
        total += 1

    print(f'DataPool populado: {total} itens → [{datapool_label}]')
    return total
src/item_processor.py — consumo robusto com distinção de erros 
from botcity.maestro.model import AutomationItemFinishStatus
import logging

logger = logging.getLogger(__name__)


class ValidationError(Exception):
    """Dado inválido — o item vai para ERROR, o bot CONTINUA."""

class SystemError(Exception):
    """Falha de infraestrutura — o bot PARA e alerta."""


def loop_datapool(maestro, datapool_label, config) -> dict:
    dp    = maestro.datapool(datapool_label)
    stats = {'total':0, 'validos':0, 'erros_item':0,
             'ambiguos':0, 'erros_sistema':0}

    while True:
        item = dp.next_item()
        if item is None:
            break                   # DataPool vazio — fim

        stats['total'] += 1
        lote_id = item.values.get('lote_id', '?')

        try:
            resultado = processar_item(item.values, config)

            if resultado['tipo'] == 'AMBIGUO':
                stats['ambiguos'] += 1
                item.report(status=AutomationItemFinishStatus.ERROR,
                            message=resultado['motivo'])
            else:
                stats['validos'] += 1
                item.report(status=AutomationItemFinishStatus.DONE,
                            message='Validação OK')

        except ValidationError as e:
            stats['erros_item'] += 1
            logger.warning(f'[{lote_id}] ValidationError: {e}')
            item.report(status=AutomationItemFinishStatus.ERROR,
                        message=str(e))
            # NÃO relança — bot continua no próximo item

        except SystemError as e:
            stats['erros_sistema'] += 1
            logger.critical(f'[{lote_id}] SystemError: {e}', exc_info=True)
            item.report(status=AutomationItemFinishStatus.ERROR,
                        message=f'ERRO DE SISTEMA: {e}')
            raise       # Relança — bot PARA

    return stats

src/secrets_provider.py — abstrai Vault e .env 
from dataclasses import dataclass
import os, logging

logger = logging.getLogger(__name__)


@dataclass
class CredenciaisMaestro:
    server: str
    login:  str
    key:    str


class SecretsProvider:
    """
    Em produção: usa Credentials Vault do BotCity/Smart Office.
    Em desenvolvimento: usa variáveis de ambiente (.env local).
    """

    def __init__(self, maestro=None):
        self._maestro      = maestro
        self._usando_vault = maestro is not None
        if not self._usando_vault:
            logger.warning(
                'SecretsProvider: usando .env local (desenvolvimento). '
                'NUNCA usar em produção.'
            )

    def maestro_credentials(self) -> CredenciaisMaestro:
        if self._usando_vault:
            cred = self._maestro.get_credential(
                'maestro-conferencia-lotes',
                'maestro-conferencia-lotes'
            )
            return CredenciaisMaestro(
                server=os.getenv('MAESTRO_SERVER', ''),
                login=cred.login,
                key=cred.password
            )
        # Fallback desenvolvimento (.env)
        return CredenciaisMaestro(
            server=os.getenv('MAESTRO_SERVER', ''),
            login=os.getenv('MAESTRO_LOGIN', ''),
            key=os.getenv('MAESTRO_KEY', ''),
        )

import asyncio, os, smtplib, logging
from enum import Enum
from email.mime.multipart import MIMEMultipart
from email.mime.text      import MIMEText
from datetime import datetime


class Severidade(Enum):
    INFO    = 'info'
    AVISO   = 'aviso'
    ERRO    = 'erro'
    CRITICO = 'critico'


ICONES = {
    Severidade.INFO:    'ℹ️',
    Severidade.AVISO:   '⚠️',
    Severidade.ERRO:    '❌',
    Severidade.CRITICO: '🚨',
}


def alerta_conclusao(total, validos, divergencias, ambiguos, duracao):
    """Envia alerta padrão de conclusão do processamento."""
    sev = Severidade.ERRO if divergencias > 15 else Severidade.INFO
    titulo = 'Conferência de Lotes Concluída'
    msg = (
        f'Registros: {total}\n'
        f'Válidos: {validos}\n'
        f'Divergências: {divergencias}\n'
        f'Ambíguos: {ambiguos}\n'
        f'Duração: {duracao}s'
    )
    enviar_alerta(titulo, msg, sev)


def enviar_alerta(titulo, mensagem, sev):
    token   = os.getenv('TELEGRAM_TOKEN', '')
    chat_id = os.getenv('TELEGRAM_CHAT_ID', '')
    if not token: return
    icone = ICONES[sev]
    texto = (
        f'{icone} {titulo}\n'
        f'Bot: bot-conferencia-lotes\n'
        f'{mensagem}\n'
        f'{datetime.now().strftime("%d/%m %H:%M")} (Manaus)'
    )
    try:
        from telegram import Bot
        asyncio.run(Bot(token=token).send_message(
            chat_id=chat_id, text=texto[:4096], parse_mode='HTML'
        ))
    except Exception as e:
        logging.getLogger(__name__).error(f'Telegram falhou: {e}')
